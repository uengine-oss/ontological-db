# Implementation Plan: 분산 클러스터와 확장성

**Branch**: `007-distributed-cluster` | **Date**: 2026-08-06 | **Spec**: [spec.md](spec.md)

## Summary

**단계적으로만 제공한다.** 스펙 Assumptions가 명시한 순서를 그대로 따른다:
읽기 복제 → 명시적 파티션 키 샤딩 → 그래프 인지 파티셔닝.

**현재 릴리스(v0.1) 상태: P0만 구현. 샤딩은 미구현이며 문서에 그렇게 표기한다.**
이것은 축소가 아니라 정직한 단계화다 — 부분 구현된 분산은 원칙 IX(ACID)를 조용히 깨뜨린다.

## Architecture

**P0 — 읽기 복제 (구현됨)**

별도 코드가 필요 없다는 것이 요점이다. 모든 그래프 구조가 일반 힙 릴레이션이므로
PostgreSQL 스트리밍 복제가 그대로 동작한다. 필요한 것은 검증뿐:
`og_check_integrity()` 를 대기 서버에서 실행해 주 서버와 동일 결과를 확인한다.

**P1 — 파티션 키 샤딩 (설계 확정, 미구현)**

- 식별자의 상위 9비트가 이미 샤드를 담고 있다(001 FR-004). 재분배 시 `local_id` 불변.
- 배치 정책은 `og_catalog.placement(graph_id, type_id, strategy, key_prop)`.
- 원격 실행은 `postgres_fdw` 위에 얹는다 — 원칙 I을 지키면서 push-down을 얻는 유일한 경로.
- 컴파일러는 이미 SQL을 뱉으므로, 분산 계획은 **동일 SQL을 원격 노드에서 실행하고
  코디네이터에서 병합**하는 형태가 된다. 홉마다 데이터를 끌어오지 않는다(FR-011).

**P2 — 그래프 인지 파티셔닝 (미착수)**
