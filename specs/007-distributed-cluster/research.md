# Phase 0 Research: 분산 클러스터

**Feature**: 007-distributed-cluster · **Date**: 2026-08-06

스펙의 Assumptions 가 plan 단계로 미룬 결정들을 여기서 확정한다. 각 항목은
**결정 / 근거 / 기각한 대안** 형식이다.

---

## R1. 원격 실행 전송 계층 — 무엇으로 노드 사이를 잇는가

**결정**: `dblink`(contrib)로 **질의 텍스트를 전송**한다. `postgres_fdw` 는 채택하지 않는다.

**근거**:

- 우리가 원격에 보내야 하는 것은 *테이블* 이 아니라 *질의* 다. `postgres_fdw` 는 원격 릴레이션을
  로컬 외부 테이블로 매핑하는 도구이고, push-down 은 그 릴레이션에 걸린 술어에 한정된다.
  그래프 패턴 하나가 `og_adj`, `og_node`, 타입 테이블 여러 개를 동시에 건드리므로 FDW 로는
  "패턴 전체를 원격에서" 실행시킬 방법이 없다 — 조인 push-down이 깨지는 순간 홉마다
  코디네이터로 행이 올라오고, 이는 스펙 FR-011 이 명시적으로 금지한 형태다.
- `dblink` 는 임의의 질의 문자열을 원격에서 실행하고 결과 집합만 받는다. 즉 **한 샤드당 왕복
  1회**가 구조적으로 보장된다(FR-012).
- 둘 다 표준 contrib 이므로 헌법 원칙 I(포크 금지)에는 차이가 없다. Supabase 를 포함한 관리형
  환경에서 `dblink` 는 설치 가능하다.

**기각한 대안**:

| 대안 | 기각 이유 |
|------|----------|
| `postgres_fdw` 외부 테이블 매핑 | 위 근거. 조인 push-down 실패 시 조용히 느려지며, 그 실패가 EXPLAIN 을 읽지 않으면 보이지 않는다 |
| Citus 위에 얹기 | 분산 테이블 정의가 Citus 의 분산 실행기에 종속된다. `og_adj` 의 배열 인접 구조는 Citus 의 co-location 모델과 맞지 않고, Citus 없는 환경에서 확장이 설치조차 되지 않는다 |
| 자체 노드 간 프로토콜(백그라운드 워커 + 소켓) | 연결 풀·인증·TLS·취소·타임아웃을 전부 다시 만들어야 한다. libpq 가 이미 하는 일이다 |

**귀결**: `dblink` 는 확장의 `requires` 에 넣지 않는다. 단일 노드 사용자가 쓰지도 않을 의존성을
설치하게 만들 이유가 없다. `og_cluster_enable()` 이 부재를 감지해 교정 가능한 오류를 낸다
(헌법 VIII).

## R2. 원격에 보내는 것은 SQL 인가 Cypher 인가

**결정**: **Cypher 를 보낸다.** 코디네이터가 컴파일한 SQL 을 보내지 않는다.

**근거**:

- 컴파일된 SQL 은 `og_data.v_17` 같은 **로컬 카탈로그의 타입 id 와 지연 생성된 뷰 이름**을
  포함한다. 이 이름들은 노드마다 다를 수 있다. 컴파일 결과를 그대로 보내면 우연히 맞는 동안만
  동작하고 타입 하나가 추가되는 순간 조용히 틀린다.
- Cypher 를 보내면 각 워커가 **자기 카탈로그로 컴파일**하고, 그 노드의 PostgreSQL 플래너가
  패턴 전체를 본다. 헌법 원칙 II 가 단일 노드에서 주는 이점이 원격에서도 그대로 성립한다.
- 재컴파일 비용은 워커의 계획 캐시(`PLAN_CACHE`)가 흡수한다.

**기각한 대안**: 컴파일된 SQL 전송 — 카탈로그 동형성을 전제해야 하는데, 그 전제를 강제할
수단이 없다.

## R3. 교차 샤드 트래버설을 어떻게 다룰 것인가 — 이 스펙에서 가장 중요한 결정

**문제**: 질의를 샤드별로 쪼개 실행하고 결과를 합치는 방식은, 패턴이 샤드 경계를 넘는 순간
**조용히 답을 누락한다**. `(a)-[:KNOWS]->(b)` 에서 a 는 샤드1, b 는 샤드2 이면 어느 샤드도 그
경로를 보지 못한다.

**결정**: **공배치 계약(co-location contract)** 을 도입한다. 배치 정책은 "이 키가 같은 데이터는
같은 샤드에 있다"를 선언하고, 시스템은 **그 계약을 깨는 엣지 생성을 거부**한다.
v0.1 은 샤드를 넘는 엣지를 만들지 않으므로, 샤드별 실행 결과의 합집합이 곧 정답이다.

**근거**:

- 부분적으로 맞는 답을 조용히 반환하는 것이 이 스펙에서 가장 나쁜 실패다(스펙 FR-020,
  SC-011 이 같은 취지를 이미 못박고 있다). 계약을 강제하면 "왜 결과가 빠졌는가"를 디버깅할
  일이 애초에 생기지 않는다.
- 테넌트/고객/문서 단위로 나뉘는 실제 그래프 워크로드의 다수가 자연히 이 계약을 만족한다.
  같은 테넌트 안에서만 엣지가 생기기 때문이다.
- 계약을 못 지키는 워크로드에는 **분산 트래버설이 필요하다**고 정직하게 말하는 편이,
  틀린 답을 빠르게 주는 것보다 낫다. 분산 트래버설(반복 확장 + 배치 원격 확장)은 Phase 2다.

**기각한 대안**:

| 대안 | 기각 이유 |
|------|----------|
| 교차 샤드 엣지를 허용하고 코디네이터가 홉마다 병합 | FR-011 위반. 그리고 이 경로를 열어두면 "느린데 왜 느린지 모르는" 질의가 생긴다 |
| 엣지를 양쪽 샤드에 이중 저장 | 쓰기 원자성이 두 샤드에 걸리고(2PC 상시), 중복 제거를 코디네이터가 매번 해야 한다. 읽기가 아니라 쓰기를 두 배로 비싸게 만든다 |
| 그냥 허용하고 문서에만 "주의" 표기 | 조용한 오답. 헌법 IX/VIII 위반 |

**탈출구**: `allow_cross_shard := true` 로 계약을 명시적으로 해제할 수 있다. 해제하면 분산
트래버설이 불완전할 수 있음을 **질의 시점에 경고가 아니라 계획 메타데이터로** 드러낸다.

## R4. 어떤 질의를 push-down 할 수 있는가 (분해 가능성)

**결정**: 집계는 **부분 집계 + 코디네이터 병합**으로 재작성한다. 분해 불가능한 연산은
**거부한다**(조용한 오답 금지).

| Cypher 연산 | 샤드에서 | 코디네이터에서 |
|------------|---------|--------------|
| `count(x)`, `count(*)` | `count` | `sum` |
| `sum(x)` | `sum` | `sum` |
| `min/max(x)` | `min/max` | `min/max` |
| `avg(x)` | `sum(x)`, `count(x)` 두 개로 분해 | `sum/sum` |
| `collect(x)` | `collect` | 배열 연결 |
| `ORDER BY … LIMIT n` | 같은 정렬 + `LIMIT skip+n` | 병합 정렬 후 절단 |
| `count(DISTINCT x)` | — | **거부**: 샤드 부분 결과로는 전역 중복 제거가 불가능 |
| `percentile`, `stddev` | — | **거부** |

**근거**: 대수적으로 분해 가능한 집계만 병합이 정확하다. 나머지를 "대략 맞게" 처리하는 것은
SC-011 과 같은 종류의 거짓말이다.

## R5. 분산 쓰기의 원자성

**결정**: 한 샤드로 라우팅되면 **원격 로컬 트랜잭션 그대로**(2PC 없음), 여러 샤드를 건드리면
**2PC**(`PREPARE TRANSACTION` → 전원 성공 시 `COMMIT PREPARED`, 하나라도 실패 시 전원
`ROLLBACK PREPARED`). 코디네이터는 결정 시점을 `og_data.og_dtxn` 에 먼저 기록한다.

**근거**: 단일 샤드 쓰기(공배치 계약 아래의 정상 경로)에 2PC 비용을 물릴 이유가 없다.
2PC 는 실제로 필요할 때만 켜진다. 결정 로그가 있어야 코디네이터가 죽은 뒤 `og_cluster_recover()`
가 미결 트랜잭션을 정리할 수 있다.

**전제**: 워커의 `max_prepared_transactions > 0`. 0 이면 다중 샤드 쓰기를 **시작하지 않고**
설정 방법을 알려주며 거부한다(헌법 VIII: 교정 가능한 오류).

## R6. 샤드 식별자와 재분배 안정성

**결정**: 001 이 이미 예약한 상위 9비트를 사용한다. 각 워커는 `og_catalog.setting['shard_id']`
로 자기 샤드를 알고, `alloc_id` 가 그 값을 식별자에 심는다. 기본값 0 = 단일 노드.

**근거**: 식별자에서 샤드를 상수 시간에 읽을 수 있으므로 라우팅에 카탈로그 조회가 필요 없다.
재분배는 `local_id` 를 보존하므로(FR-008) 재분배 후에도 참조가 깨지지 않는다 — 단, 재분배가
샤드 비트를 바꾸면 이전 식별자는 위치 힌트로서 무효가 되므로, 재분배는 **위치 힌트를 카탈로그
쪽 진실(`og_catalog.shard`)로 다시 확인**하는 경로를 갖는다.

## R7. 단일 노드 성능 보호 (헌법 VII, 스펙 FR-027/028)

**결정**: 분산 계층은 **별도 함수 표면**(`og_cluster_*`)으로만 진입한다. `og_cypher`,
`og_cypher_sql`, `og_vector_search` 등 기존 경로에는 분산 분기 자체를 넣지 않는다.

**근거**: 런타임 플래그 분기조차 넣지 않으면 "분산 때문에 느려졌다"가 성립할 수 없다.
측정으로 증명하는 것보다 구조로 불가능하게 만드는 편이 강하다. `og_cluster_enable()` 이
꺼져 있으면 클러스터 카탈로그는 빈 테이블 몇 개일 뿐이다.

**검증**: 회귀 스위트가 클러스터 비활성 상태에서 `og_cypher_sql` 의 출력에 분산 연산자가
없음을 확인한다.

## R8. 테스트를 어떻게 실행 가능하게 만드는가

**결정**: **같은 인스턴스 안의 여러 데이터베이스**를 워커로 쓴다(`dblink` 루프백).

**근거**: 클러스터 의미론(라우팅, 병합, 2PC, 장애 시 명시적 오류)은 프로세스 경계가 아니라
연결 경계에서 결정된다. 별도 인스턴스는 네트워크 지연을 재현할 뿐 정확성 관점의 커버리지는
동일하고, CI 가 컨테이너 여러 개를 띄우지 않아도 된다.

**한계 인정**: 이 하네스로는 네트워크 분단·지연 특성(SC-004 의 전송량, SC-008 의 장애 전환
시간)은 측정하지 못한다. 그 지표들은 009 벤치마크 하네스의 다중 컨테이너 구성에 속한다.
