# Feature Specification: 에이전트 네이티브 인터페이스 (Agent-Native Interface)

**Feature Branch**: `008-agent-native-interface`

**Created**: 2026-08-05

**Status**: Draft

**Input**: User description: "AI 에이전트 시대에 적합한 그래프 DB를 설계하자"

## 개요

기존 그래프 DB는 사람 개발자를 위해 설계됐다. 스키마는 문서로 설명되고, 오류는 사람이 읽고,
질의는 사람이 검증한다. 그런데 이제 질의를 쓰는 주체가 LLM 에이전트다.

에이전트는 사람과 다르게 실패한다: 없는 레이블을 지어내고, 관계 방향을 뒤집고, 조합 폭발
질의를 만들고, 확신에 차서 틀린다. 그리고 사람과 다른 것을 필요로 한다: 기계 판독 가능한
스키마, 교정 가능한 오류, 답의 출처, "언제 기준으로 참인가".

이 스펙은 그 요구를 DB의 1급 기능으로 정의한다(헌법 원칙 VIII).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 에이전트가 스키마를 정확히 파악한다 (Priority: P1)

LLM 에이전트가 질의를 만들기 전에 스키마를 조회한다. 어떤 타입이 있고, 어떤 관계가 어느
타입을 잇고, 어느 방향인지, 실제 값이 어떻게 생겼는지를 토큰 예산 안에서 받는다.

**Why this priority**: 에이전트 Cypher 생성 정확도는 스키마 정보 품질에 거의 전적으로
비례한다. 이것이 이 스펙에서 가장 중요한 단 하나의 기능이다.

**Independent Test**: 표준 질문 세트에 대해 스키마 introspection만 제공하고 LLM이 생성한
Cypher의 실행 성공률과 정답률을 측정한다.

**Acceptance Scenarios**:

1. **Given** 타입 계층과 관계가 정의된 그래프에서, **When** 에이전트가 스키마 요약을
   요청하면, **Then** 타입 목록, 상속 관계, 관계 타입과 양 끝 타입, 방향, 프로퍼티와 그
   데이터타입이 구조화된 형식으로 반환된다.
2. **Given** 타입이 1,000개인 대형 스키마에서, **When** 토큰 예산을 지정해 요약을 요청하면,
   **Then** 예산 안에 들어가도록 중요도 기준으로 축약된 스키마가 반환되고 축약 사실이
   표시된다.
3. **Given** 특정 타입에 대해 상세 정보를 요청하면, **When** 응답을 확인하면, **Then**
   제약, 카디널리티, 값 분포 통계, 실제 값 예시가 포함된다.
4. **Given** 스키마가 변경되면, **When** 다시 조회하면, **Then** 변경이 즉시 반영되고
   스키마 버전이 함께 반환된다.
5. **Given** 질문이 자연어로 주어지면, **When** 관련 스키마 부분을 요청하면, **Then** 질문과
   관련된 타입·관계만 선별해 반환된다.

### User Story 2 - 틀린 질의가 스스로 고쳐진다 (Priority: P1)

에이전트가 존재하지 않는 레이블 `:Custmer` 를 사용한다. 오류는 "구문 오류"가 아니라
"`Custmer` 타입이 없습니다. 가장 가까운 후보: `Customer`(편집거리 1), `CustomerOrder`" 를
기계 판독 가능한 형식으로 알려준다. 에이전트는 한 번의 재시도로 성공한다.

**Why this priority**: 에이전트의 재시도 루프 효율이 전체 시스템 지연·비용을 좌우한다.

**Independent Test**: 흔한 오류 유형별 질의를 실행하고, 오류 정보만으로 자동 교정이
성공하는 비율을 측정한다.

**Acceptance Scenarios**:

1. **Given** 존재하지 않는 타입 이름이 사용되면, **When** 실행하면, **Then** 오류에 가장
   가까운 유효 후보 목록이 포함된다.
2. **Given** 관계 방향이 반대로 지정되면, **When** 실행하면, **Then** 빈 결과 대신 "이
   방향으로는 해당 관계가 존재하지 않음, 반대 방향에는 N건 존재" 정보가 제공된다.
3. **Given** 존재하지 않는 프로퍼티가 참조되면, **When** 실행하면, **Then** 해당 타입의
   유효 프로퍼티 목록이 오류에 포함된다.
4. **Given** 모든 오류에 대해, **When** 응답을 확인하면, **Then** 안정적인 오류 코드,
   구조화된 상세 정보, 사람이 읽을 메시지가 모두 포함된다.
5. **Given** 결과가 비어 있는 질의에서, **When** 진단을 요청하면, **Then** 어느 패턴 단계에서
   결과가 0이 되었는지 알려준다.

### User Story 3 - 답의 근거를 추적할 수 있다 (Priority: P1)

RAG 파이프라인이 답변을 생성하며 인용을 붙인다. 어떤 노드·관계·경로가 결과에 기여했는지,
그 데이터가 어디서 왔는지를 DB가 알려준다.

**Why this priority**: 근거 없는 답은 AI 시스템에서 쓸 수 없다. 그래프 DB가 벡터 DB보다
나은 핵심 이유이기도 하다.

**Independent Test**: 집계·추론이 포함된 질의에 출처 추적을 켜고, 반환된 근거로 결과를
재현할 수 있는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 다중 홉 질의에서, **When** 출처 추적을 활성화하면, **Then** 각 결과 행에 기여한
   노드·관계 식별자와 경로가 반환된다.
2. **Given** 추론된 사실이 결과에 포함될 때, **When** 근거를 요청하면, **Then** 어떤 규칙과
   어떤 명시 사실로부터 도출되었는지 반환된다.
3. **Given** 집계 결과에서, **When** 근거를 요청하면, **Then** 집계에 기여한 원본 엔티티를
   전개할 수 있다.
4. **Given** 데이터에 출처 메타데이터(소스 문서, 적재 시각, 신뢰도)가 부착되어 있을 때,
   **When** 질의하면, **Then** 결과와 함께 조회 가능하다.
5. **Given** 출처 추적이 비활성화되면, **When** 질의를 실행하면, **Then** 추적으로 인한
   오버헤드가 발생하지 않는다.

### User Story 4 - 시간에 따른 사실을 묻는다 (Priority: P2)

에이전트가 "3개월 전 기준으로 이 회사의 자회사는?"을 묻는다. 그래프는 사실의 유효 기간과
기록 시각을 보존하므로 과거 시점 질의가 가능하다.

**Why this priority**: 지식 그래프의 신뢰성과 감사(audit)에 필수적이고, 에이전트가 자신의
과거 판단을 검증하는 데 필요하다. 다만 기본 기능이 먼저 안정화되어야 한다.

**Independent Test**: 시간에 따라 변하는 데이터를 넣고 여러 시점 질의의 정확성을 검증한다.

**Acceptance Scenarios**:

1. **Given** 이력이 보존되는 그래프에서, **When** 과거 시점을 지정해 질의하면, **Then**
   그 시점의 그래프 상태가 반환된다.
2. **Given** 사실의 유효 기간(valid time)과 기록 시각(transaction time)이 구분되어 있을 때,
   **When** 각각으로 질의하면, **Then** 서로 다른 올바른 결과가 반환된다.
3. **Given** 이력 보존이 꺼진 타입에 대해, **When** 과거 시점 질의를 하면, **Then** 이력이
   없다는 명확한 오류가 반환된다(잘못된 현재 값 반환 금지).
4. **Given** 특정 엔티티의 변경 이력을 요청하면, **When** 조회하면, **Then** 시간순 변경
   목록이 반환된다.

---

### User Story 5 - 에이전트가 안전하게 격리된다 (Priority: P1)

플랫폼 운영자가 에이전트에게 그래프 접근을 허용하되, 폭주 질의·과도한 쓰기·권한 초과를
막는다. 에이전트가 무엇을 했는지 전부 기록된다.

**Why this priority**: 자율 에이전트에게 DB 접근을 주는 것은 위험하다. 안전장치 없이는
프로덕션 도입이 불가능하다.

**Independent Test**: 악의적/폭주 질의 시나리오를 에이전트 역할로 실행하고 차단 여부와 감사
로그 완전성을 검증한다.

**Acceptance Scenarios**:

1. **Given** 에이전트 역할에 리소스 상한이 설정되어 있고, **When** 조합 폭발 질의를 실행하면,
   **Then** 상한에서 중단되고 어떤 상한을 넘었는지 반환된다.
2. **Given** 읽기 전용 에이전트 역할에서, **When** 쓰기 질의를 시도하면, **Then** 거부된다.
3. **Given** 쓰기 권한이 있는 에이전트가 대량 삭제를 시도할 때, **When** 영향 행 수가 임계치를
   넘으면, **Then** 사전 확인(dry-run) 없이는 거부된다.
4. **Given** 에이전트가 질의를 실행하면, **When** 감사 로그를 확인하면, **Then** 누가, 언제,
   어떤 질의를, 어떤 결과 크기로 실행했는지 기록되어 있다.
5. **Given** 에이전트 역할에 접근 정책(005)이 적용되면, **When** 질의를 실행하면, **Then**
   권한 범위를 벗어난 데이터가 반환되지 않는다.

---

### User Story 6 - 에이전트가 질의 비용을 미리 안다 (Priority: P2)

에이전트가 질의를 실행하기 전에 예상 비용과 결과 크기를 확인한다. 너무 비싸면 질의를 다시
쓴다.

**Why this priority**: 에이전트가 스스로 판단해 폭주를 피하게 하는 것이 사후 차단보다 낫다.

**Independent Test**: 다양한 질의의 예상 비용과 실제 비용의 상관관계를 측정한다.

**Acceptance Scenarios**:

1. **Given** 질의가 주어지면, **When** dry-run을 요청하면, **Then** 실행하지 않고 예상 결과
   행 수, 방문 노드 수, 예상 시간이 반환된다.
2. **Given** 예상 비용이 임계치를 넘으면, **When** 응답을 확인하면, **Then** 경고와 함께
   질의를 좁힐 수 있는 제안(추가 가능한 필터, 사용 가능한 인덱스)이 포함된다.
3. **Given** dry-run 결과와 실제 실행을 비교하면, **When** 여러 질의에 대해 측정하면,
   **Then** 예측이 유의미한 상관관계를 갖는다.

---

### User Story 7 - 표준 프로토콜로 도구에 붙는다 (Priority: P2)

에이전트 개발자가 MCP(Model Context Protocol) 서버로 이 DB를 연결한다. 스키마 조회, 질의,
결과 해석이 표준 도구 인터페이스로 노출된다.

**Why this priority**: 생태계 채택 경로다. 다만 위 기능들이 없으면 껍데기만 노출하는 셈이다.

**Independent Test**: MCP 클라이언트로 연결해 스키마 조회 → 질의 생성 → 실행 → 교정 루프를
종단 실행한다.

**Acceptance Scenarios**:

1. **Given** MCP 서버가 실행 중일 때, **When** 표준 MCP 클라이언트가 연결하면, **Then**
   스키마 조회·질의 실행·비용 추정 도구가 노출된다.
2. **Given** 에이전트가 MCP를 통해 질의하면, **When** 오류가 발생하면, **Then** 구조화된
   교정 정보가 도구 응답에 포함된다.
3. **Given** MCP 연결에 역할이 지정되면, **When** 질의를 실행하면, **Then** 그 역할의 권한과
   리소스 상한이 적용된다.

---

### Edge Cases

- **거대 스키마**: 타입 1만 개 스키마를 토큰 예산 안에 요약할 때 무엇을 버릴지의 기준.
- **모호한 자연어**: 질문과 관련된 스키마 선별이 잘못된 부분을 고를 때의 fallback.
- **에이전트 재시도 루프**: 같은 오류를 반복하는 에이전트에 대한 루프 차단.
- **출처 추적의 폭증**: 수백만 행 결과에 대한 출처 정보가 결과보다 커질 때의 상한.
- **이력 저장 비용**: 고빈도 갱신 데이터의 이력이 무한 증가할 때의 보존 정책.
- **시점 질의와 스키마 변경**: 과거 시점의 데이터가 당시 스키마와 현재 스키마가 다를 때의 해석.
- **감사 로그의 민감 정보**: 질의 텍스트에 개인정보가 포함될 때의 마스킹.
- **동시 에이전트**: 다수 에이전트가 동시에 쓰기를 시도할 때의 충돌과 재시도 안내.

## Requirements *(mandatory)*

### Functional Requirements

**스키마 Introspection**

- **FR-001**: 시스템은 전체 스키마(타입 계층, 관계 타입과 양 끝 타입, 방향, 프로퍼티,
  데이터타입, 제약)를 기계 판독 가능한 구조화 형식으로 제공해야 한다.
- **FR-002**: 스키마 응답은 토큰/크기 예산을 지정할 수 있어야 하며, 예산 초과 시 중요도 기준
  축약과 축약 사실 표시가 이루어져야 한다.
- **FR-003**: 시스템은 타입별 통계(인스턴스 수, 프로퍼티 값 분포, 카디널리티, 대표 값 예시)를
  제공해야 한다.
- **FR-004**: 시스템은 자연어 질문과 관련된 스키마 부분집합을 선별해 반환하는 기능을 제공해야
  한다.
- **FR-005**: 스키마 응답에는 스키마 버전이 포함되어야 하며, 에이전트가 캐시 무효화를 판단할
  수 있어야 한다.
- **FR-006**: 시스템은 자주 쓰이는 질의 패턴 예시(스키마 기반 템플릿)를 제공할 수 있어야 한다.

**오류와 교정**

- **FR-007**: 모든 오류는 안정적인 오류 코드, 구조화된 상세 정보, 사람이 읽을 메시지를 함께
  제공해야 한다.
- **FR-008**: 존재하지 않는 타입/프로퍼티/관계 참조 시 오류에 유사도 기반 유효 후보 목록이
  포함되어야 한다.
- **FR-009**: 관계 방향 오류는 빈 결과가 아니라 "반대 방향에 N건 존재" 정보와 함께 제공되어야
  한다.
- **FR-010**: 시스템은 결과가 0인 질의에 대해 어느 패턴 단계에서 결과가 소실되었는지 진단할
  수 있어야 한다.
- **FR-011**: 오류 형식은 버전 간 안정적이어야 하며, 변경 시 하위 호환을 유지하거나 명시적
  버전을 부여해야 한다.

**출처(Provenance)**

- **FR-012**: 시스템은 질의 결과에 기여한 노드·관계·경로를 반환하는 출처 추적 모드를 제공해야
  한다.
- **FR-013**: 추론된 사실은 도출에 사용된 규칙과 명시 사실을 근거로 제공해야 한다.
- **FR-014**: 집계 결과는 기여 원본 엔티티로 전개 가능해야 한다.
- **FR-015**: 시스템은 데이터에 출처 메타데이터(소스, 적재 시각, 신뢰도, 작성 주체)를 부착하고
  질의할 수 있어야 한다.
- **FR-016**: 출처 추적은 선택적이어야 하며, 비활성화 시 성능 오버헤드가 없어야 한다.
- **FR-017**: 출처 정보에는 크기 상한이 적용되어야 하며, 초과 시 요약과 함께 절단 사실이
  표시되어야 한다.

**시간(Temporal)**

- **FR-018**: 시스템은 타입 단위로 이력 보존을 켜고 끌 수 있어야 한다.
- **FR-019**: 시스템은 유효 시각(valid time)과 기록 시각(transaction time)을 구분해 저장·질의할
  수 있어야 한다.
- **FR-020**: 시스템은 과거 시점을 지정한 질의를 지원해야 한다.
- **FR-021**: 이력이 보존되지 않은 대상에 과거 시점 질의를 하면 명확한 오류를 반환해야 하며,
  현재 값을 대신 반환해서는 안 된다.
- **FR-022**: 시스템은 엔티티 단위 변경 이력 조회를 제공해야 한다.
- **FR-023**: 시스템은 이력 보존 정책(기간, 용량 상한)을 설정할 수 있어야 한다.

**안전장치**

- **FR-024**: 시스템은 역할 단위로 질의 리소스 상한(시간, 메모리, 방문 노드/엣지 수, 결과 행
  수)을 설정할 수 있어야 한다.
- **FR-025**: 시스템은 역할 단위로 읽기 전용/쓰기 허용을 구분해야 한다.
- **FR-026**: 영향 범위가 임계치를 넘는 쓰기·삭제는 사전 확인 없이 거부되어야 한다.
- **FR-027**: 시스템은 모든 질의 실행을 감사 로그로 기록해야 하며, 주체·시각·질의·결과 크기·
  소요 시간을 포함해야 한다.
- **FR-028**: 감사 로그는 민감 정보 마스킹 정책을 적용할 수 있어야 한다.
- **FR-029**: 반복 실패하는 질의 패턴에 대해 시스템은 속도 제한을 적용할 수 있어야 한다.

**비용 예측**

- **FR-030**: 시스템은 질의를 실행하지 않고 예상 결과 행 수, 방문 노드 수, 예상 시간을 반환하는
  dry-run을 제공해야 한다.
- **FR-031**: 예상 비용이 임계치를 넘으면 질의를 좁힐 수 있는 구체적 제안이 함께 제공되어야
  한다.

**프로토콜 노출**

- **FR-032**: 시스템은 MCP 호환 서버를 제공하여 스키마 조회, 질의 실행, 비용 추정, 오류 교정
  정보를 도구로 노출해야 한다.
- **FR-033**: MCP 연결은 역할 기반 권한과 리소스 상한을 적용받아야 한다.
- **FR-034**: 모든 에이전트용 기능은 MCP 없이 표준 SQL 인터페이스로도 접근 가능해야 한다.

### Key Entities

- **Schema Summary**: 에이전트용 스키마 표현. 요약 수준, 토큰 예산, 축약 여부, 스키마 버전을
  갖는다.
- **Structured Error**: 오류 코드, 위치, 원인, 후보 제안, 사람용 메시지.
- **Provenance Record**: 결과 행 → 기여 노드/관계/경로/규칙 매핑.
- **Source Metadata**: 데이터에 부착된 출처 정보(소스 식별자, 적재 시각, 신뢰도, 작성 주체).
- **Temporal Fact**: 유효 시각 구간과 기록 시각을 갖는 사실.
- **Agent Role**: 에이전트 주체의 권한·리소스 상한·감사 설정.
- **Query Audit Entry**: 감사 로그의 한 항목.
- **Cost Estimate**: dry-run 결과. 예상 행 수, 방문 규모, 시간, 개선 제안.
- **MCP Tool Descriptor**: MCP로 노출되는 도구 정의.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 표준 자연어 질문 100개에 대해, 스키마 introspection만 제공한 LLM이 생성한
  Cypher의 **1회 실행 성공률이 80% 이상**이다.
- **SC-002**: 구조화된 오류 정보를 제공했을 때, **1회 재시도 내 교정 성공률이 90% 이상**이다.
- **SC-003**: 타입 1,000개 스키마가 **4,000 토큰 이내**로 요약되며, 그 요약만으로 SC-001의
  성공률이 **10%p 이내** 저하에 그친다.
- **SC-004**: 출처 추적 활성화 시 질의 지연 증가가 **50% 이내**이고, 비활성화 시 오버헤드가
  **측정 불가 수준**이다.
- **SC-005**: 반환된 출처 정보로 결과를 재현하는 검증이 **100%** 성공한다.
- **SC-006**: 과거 시점 질의 결과가 해당 시점의 실제 상태와 **100% 일치**한다.
- **SC-007**: 폭주 질의 시나리오 **50종 전부**가 리소스 상한에서 차단되고, 어떤 상한을
  초과했는지 반환된다.
- **SC-008**: 모든 질의 실행의 **100%** 가 감사 로그에 기록된다.
- **SC-009**: dry-run 예상 결과 행 수와 실제 행 수의 상관계수가 **0.8 이상**이다.
- **SC-010**: MCP 클라이언트에서 스키마 조회 → 질의 → 오류 교정 → 재질의 루프가 **사람 개입
  없이** 완료되는 시나리오가 자동 테스트로 통과한다.
- **SC-011**: 이력 보존 활성화로 인한 쓰기 처리량 저하가 **40% 이내**다.

## Assumptions

- 타입 카탈로그와 제약은 스펙 **002-ontology-type-system** 이 제공하며, 본 스펙은 그것을
  에이전트 친화 형식으로 노출한다.
- 질의 리소스 상한의 실행 계층 강제는 스펙 **003-cypher-query-engine** 이 담당하고, 본 스펙은
  역할 단위 정책과 노출을 정의한다.
- 접근 제어의 기반은 스펙 **005-postgres-supabase-interop** 의 접근 정책이다.
- 추론 근거 제공은 스펙 **002** 및 **006-semantic-web-adapters** 의 추론 기능에 의존한다.
- 벡터 기반 검색 결과의 출처 표시는 스펙 **004-vector-hybrid-search** 와 연동된다.
- LLM 호출(자연어 → Cypher 변환 자체)은 본 시스템의 범위가 아니다. 시스템은 에이전트가 정확한
  질의를 만들 수 있도록 **정보와 안전장치를 제공**한다. 다만 평가를 위해 참조 에이전트 구현과
  질문 세트를 벤치마크(009)에 포함한다.
- MCP는 현재 사실상 표준으로 채택하되, 프로토콜이 변해도 코어 기능이 SQL로 접근 가능하도록
  분리한다.
- 이력 보존은 기본 비활성이며, 필요한 타입에만 켠다(비용 때문).
