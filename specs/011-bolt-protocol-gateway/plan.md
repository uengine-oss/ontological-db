# Implementation Plan: Bolt 프로토콜 게이트웨이

**Branch**: `011-bolt-protocol-gateway` | **Date**: 2026-08-06 | **Spec**: [spec.md](spec.md)

## Summary

Bolt를 말하는 **별도 프로세스**를 두고, 받은 Cypher를 `og_cypher()` 로 실행해 결과를
PackStream으로 돌려준다. 프로토콜 계층은 의미론을 갖지 않는다 — 파서도, 플래너도,
캐시도 없다. Cypher 한 글자도 게이트웨이에서 해석되지 않는다.

**핵심 설계 결정**

1. **코어가 아니라 엣지에 둔다.** 배경 워커(background worker)로 확장 안에 넣으면
   "확장 하나면 끝"이라는 이야기에는 맞지만, SPI는 스레드 안전하지 않아 세션 간 질의가
   직렬화된다 — 그 대가로 얻는 것이 설치 편의뿐이라면 잘못된 거래다. 게이트웨이는
   연결마다 PostgreSQL 연결을 갖는 평범한 프로세스이고, 동시성은 PostgreSQL이 이미
   해결한 방식으로 해결된다. 헌법 원칙 VI("코어는 하나, 표준은 어댑터로")의 프로토콜 판이다.
2. **인증 저장소를 만들지 않는다.** `HELLO`가 나르는 자격 증명으로 PostgreSQL에 접속한다.
   접속에 실패하면 그게 인증 실패다. 권한·RLS·감사가 하나로 유지되며, 이것이 003 FR-024a가
   지키려던 바로 그 성질이다.
3. **필드 이름은 파서에서 가져온다.** `og_cypher()` 는 jsonb 객체를 돌려주고 jsonb는 키를
   정렬하므로, 행에서 필드 순서를 복원할 수 없다. 엔진에 `og_cypher_columns(query)` 를
   추가해 `RETURN` 절의 순서를 파서가 직접 알려주게 한다 — 게이트웨이가 Cypher를 다시
   읽는 일은 없다.
4. **연결 하나에 스레드 하나.** 게이트웨이는 상태가 없고 세션은 서로 독립이다. 비동기
   런타임을 들이지 않는 이유이며, 동시성 한계는 PostgreSQL 연결 수 한계와 같아진다.

## Technical Context

**Language**: Rust (헌법 기술 제약: 저장소 전체 Rust 일관). 게이트웨이는 pgrx가 아닌
평범한 바이너리이며, 확장 ABI와 무관하다.

**Dependencies**: `postgres`(동기 클라이언트), `serde_json`. 프로토콜 구현은 직접 쓴다 —
Bolt 서버 크레이트를 쓰면 지원 매트릭스를 우리가 통제하지 못한다(FR-020).

**Testing**: PackStream 왕복 단위 테스트(`cargo test`), 그리고 **공식 Neo4j 드라이버로
공식 Movie 샘플을 실행하는 통합 테스트** — `tests/neo4j-movies/run.py` 의 Bolt 단계.
헌법 원칙 X의 적합성 판: 우리가 만든 클라이언트로 우리 서버를 테스트하는 것은 증거가 아니다.

**Performance Goals**: 게이트웨이는 프로토콜 변환 비용만 추가한다. 같은 질의를 PostgreSQL
경로로 직접 실행한 지연시간 대비 오버헤드를 측정해 문서화한다.

|------|------|------|
| I. 포크가 아닌 확장 | ✅ | PostgreSQL 커널·확장 ABI 모두 무변경. 게이트웨이는 평범한 클라이언트 |
| II. Cypher 1급 | ✅ | Bolt는 Cypher를 나르는 또 하나의 전송 계층. 언어는 003 하나 |
| III. 저장구조 | ✅ | 저장 계층 무관 |
| IV. 온톨로지 우선 타이핑 | ✅ | 002 카탈로그 그대로. Bolt가 타입을 우회하지 않는다 |
| V. 벡터 | ✅ | 해당 없음 |
| **VI. 코어는 하나, 어댑터는 엣지** | ✅ | 이 스펙의 형태 자체가 원칙 VI다. 질의 경로는 `og_cypher()` 하나 |
| VII. 확장성 | ⚠️ 부분 | `ROUTE`는 단일 서버 응답만. 진짜 라우팅은 007 범위 — 아래 Complexity Tracking |
| VIII. 에이전트 네이티브 | ✅ | 오류 메시지의 교정 제안이 `FAILURE`로 그대로 전달된다 |

**003 FR-024a와의 관계**: FR-024a는 Bolt를 비목표로 선언했다. 이 스펙이 그 조항을
대체하되, 조항이 지키려던 성질(두 번째 인증·감사 경로를 만들지 않는다)은 설계 결정 2로
유지한다. 003 스펙의 해당 항목은 이 스펙을 가리키도록 갱신한다.

## Phasing

- **Phase 0** — PackStream v2 인코더/디코더와 청크 프레이밍. 단위 테스트로 왕복 검증.
- **Phase 1** — 핸드셰이크, `HELLO`/`RUN`/`PULL`/`RESET`/`GOODBYE`, 자동커밋 질의.
  여기까지가 "드라이버가 붙는다".
- **Phase 2** — `Node`/`Relationship` 구조체 매핑, 필드 순서(`og_cypher_columns`).
  여기까지가 "애플리케이션이 결과를 원래 코드로 읽는다".
- **Phase 3** — 명시적 트랜잭션, `db` → 그래프, 실패/`IGNORED` 상태 기계, `ROUTE`.
- **Phase 4** — 공식 샘플 앱·가이드 질의 24개를 Bolt 경로로 통과시키고, 세 경로
  (Bolt / PostgreSQL / Neo4j)의 결과를 대조한다.

## Complexity Tracking

**라우팅(`ROUTE`)은 형식만 채운다.** `neo4j://` 스킴을 쓰는 드라이버는 라우팅 테이블을
요구한다. 단일 서버 응답을 돌려주어 접속은 되게 하되, 진짜 라우팅 테이블은 스펙 007의
클러스터가 존재할 때 의미를 갖는다. 원칙 VII에 대한 부분 이탈이며 여기 기록한다.

**Bolt 5.x는 범위 밖이다.** 5.x는 `element_id` 문자열 식별자와 신규 시공간 타입을
요구한다. 4.4는 현재 드라이버들이 모두 협상 가능한 버전이므로 이식성 목표는 4.4로 충족되며,
5.x는 지원 매트릭스에 "미지원"으로 명시된다(FR-020) — 조용히 절반만 구현하지 않는다.

**TLS는 앞단에 맡긴다.** 게이트웨이는 평문 Bolt만 종단한다. 운영에서는 TLS 종단 프록시
뒤에 두는 것을 전제하며, 이는 문서화된 한계다.
